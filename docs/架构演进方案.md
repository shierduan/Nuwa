# 女娲（Nuwa）架构演进方案

> 本文档记录 2026-10 对 Nuwa 代码库的诊断、MIT 开源项目对照分析，以及分阶段演进路线图。
>
> **核心约束：设计哲学不变。** 13 维情绪状态空间、黎曼语义场、自适应 PID 控制、
> Q-Learning 自演化、梦境记忆巩固——这五项是 Nuwa 的灵魂，任何演进都不得削弱它们。

### 1.2 已发现并修复的关键缺陷

本轮工作发现的问题不是"设计过时"，而是**多个子系统实际处于未接线状态**——
它们有完整的实现，却从未在运行中被调用。这类"沉默的失效"比代码过时更危险。

| # | 缺陷 | 影响 | 状态 |
|---|---|---|---|
| 1 | `MemoryCortex` 全部读写仍走 LanceDB 专有 API，而 zvec 模式下 `self.table` 为 `None` | **记忆系统完全不可用**：写入抛 AttributeError，检索恒返回空 | 已修复 |
| 2 | zvec 默认 metric 为 IP（内积），上层按"距离"语义解释 score | 检索结果排序**完全颠倒**，最相关的记忆排最后 | 已修复 |
| 3 | `zvec.create_and_open()` 要求路径不存在，重启后必然抛 `path exists` | **第二次启动即失败**，生产环境不可用 | 已修复 |
| 4 | 记忆 schema 缺少 `text` 字段 | 记忆正文无法入库，检索结果无内容 | 已修复 |
| 5 | `start_dreaming()` / `evolve_character()` 从未被调用 | **梦境模块是死代码**，女娲从不做梦 | 已修复 |
| 6 | 调度变量 `_dream_interval` / `_last_dream_time` / `_dream_running` 声明后零引用 | 梦境调度器不存在 | 已修复 |
| 7 | `server_async.py` 调用 `kernel.run_memory_dream()`，但该方法未定义 | `/dream` 指令必然崩溃 | 已修复 |
| 8 | `start_heartbeat()` / `stop_heartbeat()` 均为空实现 | 心跳机制不存在 | 已记录（见 §4） |
| 9 | `MemoryDreamer` 的摘要文本二次叠加时间戳前缀 | 摘要形如 `[ts] [ts] 正文` | 已修复 |
| 10 | `datetime.timestamp()` 在 Windows 上对 1970 年前本地时间抛 `OSError` | 写入崩溃 | 已修复 |
| 11 | `memory_cortex` 与 `memory_graph` / `graph_memory` 三者功能重叠 | 维护成本 ×3 | 已记录（见 §4） |
| 12 | 内核写入 `type="dialogue"`，而巩固/做梦/自演化均按 `type="raw"` 过滤 | **对话记忆永远不进入巩固流程**（静默失效） | 已修复 |
| 13 | `SyncLLMClient` 只提供 `chat_completions_create()`，遗留组件用 OpenAI 原生 `chat.completions.create()` | 做梦时 LLM 调用抛 AttributeError，摘要/人格演化全部失败 | 已修复 |
| 14 | 同步 LLM 调用在 `asyncio.run()` 新建的事件循环中执行，而 `AsyncOpenAI` 连接池绑定在主循环 | **做梦流程挂起**（无超时则永久阻塞） | 已修复 |
| 15 | `GraphEnhancedMemoryCortex` 未透传 `include_vector` 等新参数；图节点 ID 与向量库 ID 各自生成 | 聚类拿不到向量；base/graph 检索结果无法合并 | 已修复 |
| 16 | `find_max_similarity` / `get_stats` 等新方法未在图增强包装类中透传 | 惊奇门控在包装类下静默失效 | 已修复 |

### 1.3 架构层面的核心问题

**问题 A：记忆系统是"只增不减的仓库"，不是"会代谢的生命体"**

LanceDB 时代每次写入都追加一行向量。没有任何机制回答：
这段记忆值不值得记？它和已有记忆重复吗？旧事实被新事实推翻时怎么办？

**问题 B：情绪谱是"输入"，不是"变量"**

13 维情绪状态是 Nuwa 最独特的资产，但当前只用于两个地方：
1. 检索时的情绪一致性加权（`recall_by_emotion`）
2. Prompt 注入

情绪**不参与记忆的存亡**——一段"用户说害怕打雷"和十段"好的谢谢"
在记忆库里的权重是一样的。这是巨大浪费。

**问题 C：记忆没有时间尺度**

`memory_dreamer` 有 `HALF_LIFE_DAYS = 7.0` 的衰减公式，但它只在
"做梦时对单簇打分"这一个场景生效，不参与日常的写入决策与检索排序。

## 二、MIT 开源项目对照分析

调研范围：MIT 协议的 AI Agent / 记忆系统项目，共 7 个。

### 2.1 mnemos — Biomimetic Memory Architectures ⭐ 主要参考

**仓库**：`github.com/anthony-maio/mnemos` | **协议**：MIT
**定位**：神经科学启发的 LLM Agent 记忆库，五个可组合机制。

| 机制 | 原理 | 消融结论 |
|---|---|---|
| SurprisalGate | 预测编码：写入前评估信息量，低惊奇度丢弃 | 默认阈值下减少 **40%** 存储噪声 |
| MutableRAG | 再巩固：检索时标记 labile，后台检测矛盾并**覆盖**而非追加 | 解决"旧事实永不更新" |
| AffectiveRouter | 杏仁核过滤：valence/arousal/complexity 三轴，检索打分 = 余弦×0.7 + 状态匹配×0.3 | 受控测试下 **100%** 状态一致召回 |
| SleepDaemon | 海马-新皮层巩固：情景缓冲 → 空闲时 LLM 提取语义事实 → 剪枝 | — |
| SpreadingActivation | Collins & Loftus 扩散激活：种子节点注入能量，沿边每跳衰减 20% | 20% 衰减下概念链召回 4/4 节点（90% 衰减仅 1/4） |

**对 Nuwa 的价值**：
- SurprisalGate → 直接补上"什么该记"（Nuwa 原本完全缺失）
- MutableRAG → 直接补上"事实如何更新"（Nuwa 的 `fact_book` 只能填不能改）
- AffectiveRouter → 与 Nuwa 现有的情绪加权检索同构，可互为印证
- SleepDaemon → 与 Nuwa 原创的梦境模块同构，**是 Nuwa 更早的同类设计**

**已采纳**：SurprisalGate、MutableRAG（再巩固）、SleepDaemon（分层巩固）
**未采纳**：SpreadingActivation —— Nuwa 已有 `memory_graph`（networkx 图记忆）承担该职责，但两者尚未打通（见 §4 阶段二）

### 2.2 Qianxue（千雪）— 跨平台 AI 陪伴体 ⭐ 主要参考

**仓库**：`github.com/Stevehim0/Qianxue` | **协议**：MIT
**定位**：多进程多服务的 AI 陪伴系统，**分层记忆 + 梦境巩固 + 人格演化 + 情绪节律**。

架构要点（与 Nuwa 高度同构）：
- 服务拆分：主系统 / 记忆服务 / 心跳服务 / 语音服务 / Web 管理台，统一消息路由串联
- 分层记忆：感知层 → 体验/信息双轨长期记忆 → **梦境巩固 L0→L1→L2**
- 可扩展 Agent 引擎：多轮思考 + 并行工具调用，工具注册表可插拔
- 统一抽象层：消息源（QQ/Discord/浏览器）、跨平台身份、语音多引擎
- 三级配置优先级：环境变量 > 数据库 > YAML，热更新

**对 Nuwa 的价值**：
- **L0→L1→L2 分层**是 Nuwa 梦境模块最直接的升级路径（已采纳）
- 多进程拆分：Nuwa 当前单进程，Feishu 长连接已用子进程但属临时方案
- 三级配置优先级：Nuwa 已有 `NUWA_*` 环境变量覆盖，可进一步统一

**未采纳**：多进程拆分——Nuwa 定位是单机个人助理，进程内线程模型更简单可靠

### 2.3 smrti — AtomSpace 记忆引擎

**仓库**：`github.com/cyqlelabs/smrti` | **协议**：MIT
**定位**：图增强记忆 + 贝叶斯真值维护 + 性格驱动演化。

| 能力 | 细节 |
|---|---|
| 图结构记忆 | concept / belief / episode / goal 四类原子 + 类型化关系边 |
| 贝叶斯真值维护 | PLN 修订，概率 + 置信度双维度；**证据链不可变**，真值不直接改写 |
| 显著性排序 | `S = sim × (w_sim + w_sti·sti + w_conf·conf + w_lti·lti + w_val·|val|·intensity)` |
| 性格驱动 | 6 个预设 + 17 个超参数，直接调节检索与演化行为 |
| 多租户 | tenant_id 硬隔离 |
| 实体消歧 | 4 级级联：精确 → 别名 → 模糊（RapidFuzz）→ 嵌入相似 |
| 跨会话指代消解 | 抽取前先查询记忆中的显著实体作为上下文 |

**对 Nuwa 的价值**：
- **贝叶斯真值维护**是 `fact_book` 的正确升级方向：当前 `update_fact` 只有"填/不覆盖"二元语义，无法表达"这条事实有 85% 置信度"
- 显著性排序公式把 5 个信号加权组合，比 Nuwa 现有的"语义 + 情绪"两信号更完整
- 实体消歧 4 级级联：Nuwa 的 `retrieve_relevant_facts` 目前只做关键词/token 匹配

**未采纳**：多租户（Nuwa 是单用户）、16 个 MCP Server 形态（Nuwa 有自己的渠道层）

### 2.4 cogmem-agent — 认知记忆

**仓库**：`github.com/haru10mei/cogmem-agent` | **协议**：MIT
**定位**：情绪门控召回 + 自适应遗忘 + 身份演化。

- **情绪门控召回**：arousal 分数调制记忆持久度，高唤醒记忆衰减更慢
- **自适应遗忘**：可配置半衰期
- **回忆再强化**：被频繁召回的记忆获得 arousal 提升（类重固化）
- **技能学习**：追踪技能使用，自动生成新技能
- **身份管理**：自动维护 `soul.md`（人格）与 `user.md`（用户画像）
- **零必需依赖**：核心仅用 stdlib

**对 Nuwa 的价值**：
- arousal 概念与 Nuwa 的情绪谱可直接映射——**这是 Nuwa 情绪参与记忆代谢的现成范式**
- "回忆再强化"与 mnemos 的 MutableRAG 互补：一个增强强度，一个改写内容
- `soul.md` / `user.md` 双文件的身份分离思路，可映射到 Nuwa 的 `evolved_persona` 与 `fact_book`

### 2.5 LIFE — 持久身份架构

**仓库**：`github.com/TeamSafeAI/LIFE` | **协议**：MIT
**定位**：16 个 MCP Server 覆盖驱动力、情感关系、语义记忆衰减、工作线程、习得模式、日志、身份发现、创意碰撞、预测、语音。

- **Genesis 身份发现**：80 个场景分 7 阶段（觉醒/关系/伦理/权力/自我/精神/缺口），映射到 46 个特质
- **驱动力循环**：10 个 drive + 6 类 need，每轮周期推进
- **"记忆会自然衰减"**：不用的淡去，回访的留下
- **"给人建议的系统，本身在结构上就是陪伴者"**：把"引导"内化为架构属性而非 Prompt 要求

**对 Nuwa 的价值**：
- Genesis 的"身份由选择累积而成"——与 Nuwa 的 `evolved_persona` 演化路径一致，但 LIFE 的实现更系统化
- 驱动力循环（drive + need 双层）比 Nuwa 现有的 `drives`（仅 2 维：social_hunger / curiosity）丰富得多
- **"结构即性格"**的思路值得借鉴：与其在 Prompt 里要求女娲温柔，不如让她的记忆机制本身产生温柔的行为

## 三、本轮已落地的演进（Phase 0）

### 3.1 向量存储：LanceDB → zvec（完成）

**动机**：LanceDB 依赖 pyarrow + pandas（~200MB），进程内维护成本高；zvec 是阿里 Proxima 引擎的嵌入式实现，进程内运行、类 SQLite 持久化、零外部服务——更契合 Nuwa "消费级硬件上长期运行的数字生命"定位。

**改动**：
- `vector_store.py`：扩展 `MemoryStore` 抽象，新增 `fetch()`（读-改-写闭环）；`ZvecStore` 补 `text` 字段、显式 `COSINE` metric、`open`/`create` 双分支初始化、schema 校验与自动重建
- `memory_cortex.py`：全部读写路径改走 `MemoryStore` 抽象，删除约 200 行 LanceDB 专有代码与 pandas 依赖
- `dependencies.py` / `dependency_manager.py` / `requirements.txt`：依赖声明同步更新

**关键实现决策**：
1. **metric 固定 COSINE**——zvec 默认 IP，score 语义与上层相反。统一在存储层转换为"相似度"（越大越相似），上层无需感知后端差异
2. **schema 校验 + 自动重建**——字段集合、向量维度、metric 三者任一不匹配即销毁重建。记忆可从事实账本与摘要重新生成，保留旧结构反而会导致后续写入静默失败
3. **上层不感知后端**——`MemoryCortex` 只依赖 `MemoryStore` 抽象，未来切换后端零改动

### 3.2 记忆巩固层：新建 `memory_consolidation.py`

这是本轮的核心产出——**Nuwa 原创的梦境模块强化层**。

```
写入路径：
    text → SurprisalGate.evaluate() → (通过) MemoryCortex.store_memory()
                                              → ReconsolidationBook.mark_recalled()

巩固路径（做梦时）：
    原始记忆 → EmotionalDecay.classify() → 低分遗忘 / 高分保留
             → 语义聚类 → LayeredConsolidation.summarize() → L1 摘要
             → L1 汇总 → LayeredConsolidation.derive_insight() → L2 洞察
             → 洞察事实 → state.fact_book（source="dream"，只填不覆盖）
```

#### ① SurprisalGate（惊奇门控）

| 项 | 值 |
|---|---|
| 原理 | 预测加工理论：只有与预测不符、值得惊讶的信息才获得记忆资源 |
| 判定 | `find_max_similarity(text) >= 0.82` → 判为已知信息，拒绝写入 |
| 附加规则 | 长度 < 6 字符 → 判为寒暄，拒绝 |
| 失败策略 | 探测异常时**放行**——不能因门控组件故障而丢失记忆 |

对 Nuwa 的意义：女娲不再记住"好的""嗯嗯""谢谢"，但记住"用户说过他害怕打雷"。**记忆的选择性本身是一种智能表现**，这是"数字生命"生命感的直接来源。

#### ② EmotionalDecay（情绪性衰减）— Nuwa 独有

```
存续分数 = 重要性 × (1 + 1.5 × 情绪强度) × 2^(-天数/半衰期) + 0.25 × ln(1+访问次数)
```

情绪强度取自 **13 维情绪谱的最大分量**（写入记忆时快照）。这是 Nuwa 相对通用记忆系统的**结构性优势**——情绪真正参与记忆代谢，而不只是检索加权或 Prompt 装饰。

半衰期默认 14 天；低于 0.15 分的记忆在巩固期被遗忘。

#### ③ Reconsolidation（再巩固）

借鉴 mnemos 的 MutableRAG。记忆被召回后进入"可塑性窗口"（默认 300 秒），窗口期内标记为 labile。此机制为后续"矛盾检测与改写"预留了基础设施（见 §4 阶段二）。

#### ④ LayeredConsolidation（分层巩固）

| 层 | 类型 | 语义 | 生成条件 |
|---|---|---|---|
| L0 | `raw` | 原始对话，携带完整情绪与时间 | 直接写入 |
| L1 | `summary` | 语义摘要，多条相似对话压缩 | 簇内 ≥2 条，LLM 压缩 |
| L2 | `insight` | 高阶洞察，跨摘要提炼的模式 | 摘要 ≥2 条，LLM 提炼 |

**L2 洞察是 Nuwa 原创"自我认知"的载体**：女娲不只是记住说过什么，而是逐渐理解"我在与什么样的人相处"。洞察中提取的结构化事实（`user_preferences` / `interaction_style` 等）写入 `fact_book`，`source="dream"` 保证只填不覆盖用户直接陈述的事实。

#### ⑤ 周期性巩固的去重

梦境每 15 分钟一轮，若不去重，同样的摘要与洞察会反复写入，记忆库将快速膨胀。去重只在**同类型**内容间比对（摘要去重只看摘要，洞察去重只看洞察）——若与原始记忆比对，几乎逐字相同的压缩结果会被误判为重复，导致摘要层永远无法产出。阈值：摘要 0.88 / 洞察 0.85。

### 3.3 梦境调度器：从死代码到活机制

新增于 `nuwa_kernel_async.py`：

| 方法 | 职责 |
|---|---|
| `start_dream_scheduler()` | 创建 asyncio 后台任务，绑定到 `server_async.py` 的启动流程；**同时把宿主事件循环绑定给同步兼容层** |
| `_dream_loop()` | 每 `_dream_interval`（默认 900 秒）触发一次 |
| `run_dream()` | 三段式做梦：巩固层循环 → 梦境整理（聚类压缩）→ 人格演化（TWPE），全部经 `asyncio.to_thread` 避免阻塞事件循环，各阶段独立 120 秒超时 |
| `run_memory_dream()` | 布尔包装，兼容 `server_async.py` 既有的 `/dream` 指令调用 |
| `stop_dream_scheduler()` | 取消任务并在退出前保存状态 |

配套：`process_input_stream` 的对话写入改走 `consolidator.store()`（应用惊奇门控）；`_retrieve_memories` 召回后调用 `mark_recalled()`（进入可塑性窗口）。

### 3.4 事件循环绑定的必要性（关键实现细节）

做梦流程是**同步阻塞**的（`memory_dreamer` 与 `memory_consolidation` 均为同步接口），在 kernel 中通过 `asyncio.to_thread` 放到工作线程执行。这带来一个隐蔽问题：

`AsyncOpenAI` 底层的 httpx 连接池**绑定在创建它的事件循环上**。若在工作线程里用 `asyncio.run()` 新建事件循环来发起请求，连接池与新循环不匹配——表现为**请求永久挂起**而非立即报错。

解决方案（`sync_compat.py`）：

```
SyncLLMClient.set_loop(loop)          # 绑定宿主事件循环
    ↓
chat_completions_create()
    ↓ 优先
asyncio.run_coroutine_threadsafe(coro, host_loop)   # 回投到原循环执行
    ↓ 失败时回退
asyncio.run(coro)                     # 本地新循环（仅限无绑定场景）
```

绑定点：`start_dream_scheduler()`（server 入口）与 `main_async.py` 的 `initialize()`（console 入口）。

### 3.5 记忆类型分层统一

历史代码中，内核把对话记忆标记为 `"dialogue"`，而巩固层、做梦模块、自演化模块**一律按 `"raw"` 过滤**——结果是所有真实对话记忆永远不会被整理，且不报任何错。

修复方式：
- 在 `vector_store.py` 中集中定义 `MEMORY_TYPE_RAW` / `MEMORY_TYPE_SUMMARY` / `MEMORY_TYPE_INSIGHT`（L0/L1/L2）
- 全部调用点改用常量，杜绝字面量漂移
- `MemoryCortex.get_recent_memories()` 在按 `raw` 过滤时，额外合并历史遗留的 `dialogue` 类型记录，保证旧数据也能进入巩固流程

## 四、后续路线图

### 阶段一：记忆质量闭环（优先级最高）

**目标**：让记忆的"质量"可度量、可回归。

| 任务 | 说明 | 验收标准 |
|---|---|---|
| 记忆基准集 | 构建 100+ 条问答对的记忆召回基准（参考 mnemos 的 LongMemEval 做法） | 召回准确率可复现测量 |
| 显著性排序公式 | 借鉴 smrti，把语义相似度、情绪一致性、时间衰减、访问频率、重要性五信号加权组合，替换当前两信号 | 排序公式参数化可调，基准集上准确率提升可量化 |
| 事实置信度 | `fact_book` 升级为带置信度的信念账本（借鉴 smrti 的 PLN），支持"改写"而非只"填/不覆盖" | 矛盾事实可自动仲裁，保留证据链 |
| 实体消歧 | `retrieve_relevant_facts` 从关键词匹配升级为 4 级级联（精确→别名→模糊→嵌入） | 跨会话指代可正确解析 |

### 阶段二：图记忆与巩固层打通

**目标**：让扩散激活真正参与记忆检索。

- `memory_graph`（networkx）的关联边与 `memory_cortex`（zvec）的向量记忆建立双向索引
- 借鉴 mnemos 的 SpreadingActivation：种子节点注入能量，沿边按 20%/跳衰减，取能量 > 0.3 的节点
- 与语义场（黎曼几何）结合：扩散激活给出**关联性**，语义场势能给出**人格一致性**，两者加权融合
- 矛盾检测落地：可塑性窗口内，检测到高相似度但内容矛盾的新记忆 → 改写原记忆（MutableRAG 完整实现）

### 阶段三：驱动力与需求系统

**目标**：让"主动性"有数学基础。

- 借鉴 LIFE 的 drive + need 双层结构，扩展 Nuwa 现有的 2 维 `drives`（`social_hunger` / `curiosity`）到 8-10 维
- 每个 drive 有独立的衰减曲线与满足路径（如 `curiosity` 由未解答的问题累积）
- 驱动力参与主动对话触发（当前 `active_dialogue` 的触发条件是固定冷却时间）
- 与自适应 PID 联动：PID 的性能指标可改用"驱动力满足度"而非抽象的 performance

### 阶段四：身份固化（Genesis 化）

**目标**：让女娲的"自我"成为可积累的资产。

- 借鉴 LIFE 的 Genesis：分阶段的自我提问 → 选择 → 映射到特质 → 写入起源故事
- `evolved_persona`（4 个时间桶）升级为结构化特质表 + 自传体叙事
- 身份状态可导出为独立的 `soul.md`（女娲侧）与 `user.md`（用户侧），与 cogmem-agent 的双文件思路一致

### 阶段五：工程化收敛

**目标**：消除重复实现，降低维护成本。

| 问题 | 方案 |
|---|---|
| `memory_cortex` / `memory_graph` / `graph_memory` 三者重叠 | 合并为 `MemorySystem` 门面，内部按职责分层 |
| `kernel_di` / `nuwa_kernel_async` 双内核 | 保留 async 版，DI 版降级为兼容层 |
| `heartbeat` 空实现 | 实现为真正的节律调度器，承载 drive 衰减、状态自然演化、主动对话触发 |
| 记忆类型未枚举化 | `raw` / `summary` / `insight` / `fact` 提取为 `MemoryType` 枚举 |

## 五、不可动摇的设计哲学

以下五项是 Nuwa 的身份标识，任何阶段都不得为追求"现代架构"而牺牲：

| 哲学 | 体现 | 保障机制 |
|---|---|---|
| **情绪是一等公民** | 13 维情绪状态空间，情绪参与记忆代谢（EmotionalDecay）、检索加权、Prompt 构建 | 新增机制必须与情绪谱联动，而非绕过它 |
| **语义场是人格的几何表达** | 黎曼流形 + Hessian 度量张量 + 自然梯度下降 | 检索增强必须保留 `_enhance_memory_retrieval_with_semantic_field` 路径 |
| **控制论式自我调节** | 自适应 PID，PPO 代理动态调整增益 | 状态演化继续走 PID 闭环，不改为纯 LLM 决策 |
| **自我演化** | Q-Learning + 时间加权人格演化（TWPE） | 演化维度继续由记忆历史驱动，非硬编码 |
| **做梦是原创机制** | 梦境巩固 = 记忆整理 + 事实提取 + 人格演化 | 强化而非替换；本轮为梦境模块**新增**巩固层，保留原 `memory_dreamer` 全部能力 |
